# Parametric Markov Chain (pMC) Optimization Benchmark

Command-line benchmark suite for evaluating gradient estimation algorithms and linear solvers on parametric Markov chains (pMCs).

---

## 🚀 Usage

Run the benchmark using `experiment.py`:

```bash
python3 experiment.py [SETTINGS] [METHODS] [OPTIMIZERS]
```

### Example Command

```bash
python3 experiment.py -nstep 1 -ngraph 20 -ht 180 \
  -N 10 100 1000 -K 1 10 100 -zip \
  -SparseLU -BiCGSTAB \
  -LogDerivative 1000 10000 \
  -UniformPath 1000 10000 \
  -JacobiIteration 100 1000
```

The benchmark writes results to `output.csv`. A reference file `example.csv` (generated by running this exact command) is provided in the repository so you can see what to expect. Running the command produces console output similar to:

## 🛠️ Requirements & Installation

### Hardware & Environment (Paper Reference)

All experiments reported in the paper were executed on an **AWS EC2 `m6i.large`** instance:
- **CPU:** Intel Xeon Platinum 8375C @ 3.5 GHz (x86_64 architecture, 2 vCPUs) constrained to a single core for strictly deterministic, single-threaded execution
- **RAM:** 8 GiB
- **OS / Environment:** Ubuntu Linux (tested with `g++ 15.2` and `Python 3.14`)

### Software Prerequisites

- **C++ Compiler:** Supporting **C++17** or higher (e.g., `g++ >= 8` or `clang++ >= 7`).
- **Python:** Python **3.8+** with `numpy`, `sympy`, and `matplotlib`.
- **Required C++ Libraries:**
  - `Eigen3` (`<Eigen/Sparse>`)
  - `SymEngine` (`symengine/expression.h`, `derivative.h`, `eval_double.h`, `dict.h`)
  - `FLINT`, `MPFR`, `GMP` (SymEngine backends and dependencies linked via Makefile: `-lsymengine -lflint -lmpfr -lgmp`)

### Building the Project

Compile the C++ core executable via the provided `Makefile`:

```bash
make
```

This generates the target binary (`Code/main`).

To remove compiled artifacts:
```bash
make clean
```

## 🔬 Reproducing Paper Experiments

All experiment results reported in the paper are available in the `Experiments/` directory. They can be reproduced using the following commands:

### RQ1: Scalability across Graph Sizes
```bash
python3 experiment.py -ngraph 25 -nstep 1 -ht 1800 -show \
  -N 10 20 40 80 160 320 640 1280 2560 5120 10240 \
  -K 1 2 4 8 16 32 64 128 256 512 1024 -zip \
  -SparseLU -BiCGSTAB \
  -LogDerivative 1000 10000 100000 \
  -UniformPath 1000 10000 100000 \
  -JacobiIteration 100 1000
```

### RQ2: Multi-Step Optimization Trajectories
Commands for CAdamW (CAdaGrad follow the same template):
```bash
python3 experiment.py -ngraph 100 -nstep 40 -st 100 -ht 4000 -show \
  -N 5000 \
  -K 100 \
  -SparseLU -BiCGSTAB \
  -LogDerivative 10 100 1000 10000 100000 \
  -UniformPath 10 100 1000 10000 100000 \
  -CAdamW
```

Commands for SparseLU (LogDerivative follow the same template):
```bash
python3 experiment.py -ngraph 100 -nstep 40 -st 100 -ht 1800 -show \
  -N 5000 \
  -K 100 \
  -SparseLU \
  -SGD -SmallSGD -AdaGrad -Adam -AdamW -CAdamW -CAdaGrad
```

### RQ3: Sample Budget Sensitivity
Commands for $N=3000$ ($N \in \{1000,  5000, 10000\}$ follow the same template):
```bash
python3 experiment.py -ngraph 100 -nstep 1 -ht 1800 -show \
  -N 3000 \
  -K 300 \
  -SparseLU \
  -LogDerivative 10 100 1000 10000 100000 1000000 \
  -UniformPath 10 100 1000 10000 100000 1000000
```

### RQ4: Scaling under High Number of States
```bash
python3 experiment.py -ngraph 25 -nstep 1 -ht 1800 -show \
  -N 1 2 4 8 16 32 64 128 256 512 1024 2048 4096 8192 16384 32768 65536 131072 262144 \
  -K 100 \
  -SparseLU \
  -LogDerivative 1000 10000 100000 1000000
```

### RQ5: Infinite and Continuous-State pMCs
To validate the approach on infinite and continuous-state pMCs, run the standalone scripts:
```bash
python3 Code/continuous.py

```

## ⚙️ Command-Line Arguments

### 1. Benchmark & Graph Settings

| Flag | Argument Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `-N`, `--n_list` | `int [int ...]` | `[10]` | List of state counts (e.g., `-N 10 100 1000`). |
| `-K`, `--k_list` | `int [int ...]` | `[1]` | List of parametric variables per state (e.g., `-K 1 10 100`). |
| `-P`, `--p_list` | `float [float ...]` | `[None]` | Proportion of transitions relative to the full graph ($p \in [0, 1]$). Default `None` creates minimal accessible and co-accessible graphs. |
| `-zip` | *flag* | `False` | Pairs `-N` and `-K` element-wise `(N[i], K[i])` instead of computing the Cartesian product. Requires `len(N) == len(K)`. |
| `-ngraph`, `--n_graph` | `int` | `20` | Number of random graph instances generated per setting. |
| `-nstep`, `--n_step` | `int` | `None` | Number of optimization update steps per method (`1` for single gradient evaluation; `None` allows unlimited steps until timeout). |
| `-st`, `--soft_timeout` | `float` | `None` | Maximum runtime (in seconds) before the C++ optimizer triggers a soft timeout. |
| `-ht`, `--hard_timeout` | `float` | `180.0` | Maximum runtime (in seconds) before the Python subprocess terminates the C++ process. |
| `-lr`, `--learning_rate` | `float` | `None` | Optimizer learning rate. |
| `-show` | *flag* | `False` | Enables circle graph visualization during evaluation. |

### 2. Gradient Methods & Budgets

By default, all selected gradient methods use the AdamW optimizer (which was used for all paper experiments mentioned above). You can evaluate specific optimizers by adding their respective flags: -SGD, -SmallSGD, -AdaGrad, -Adam, -AdamW, -CAdamW, and -CAdaGrad (constrained AdamW and AdaGrad, which clamps parameter updates to their valid domain intervals). Multiple optimizers can be tested concurrently.

| Flag | Argument Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `-SparseLU` | *flag* | `False` | Exact sparse LU factorization solver. |
| `-BiCGSTAB` | *flag* | `False` | Iterative Biconjugate Gradient Stabilized Krylov solver. |
| `-LogDerivative`, `--LD_list` | `int [int ...]` | `[]` | Log-Derivative gradient estimation (our method); accepts sample budgets (e.g., `-LogDerivative 1000 10000`). |
| `-UniformPath`, `--UP_list` | `int [int ...]` | `[]` | Uniform Path sampling baseline; accepts sample budgets (e.g., `-UniformPath 1000 10000`). |
| `-JacobiIteration`, `--JI_list`| `int [int ...]` | `[]` | Truncated Jacobi solver baseline; accepts iteration limits (e.g., `-JacobiIteration 100 1000`). |

> **Execution Flow:** For each `(N, K, P)` configuration, a pMC graph instance is generated. All requested methods are evaluated on that exact same graph before proceeding to the next instance (repeated `n_graph` times per setting).

## 📊 Output Format (`output.csv`)

The benchmark records all runs into CSV format containing the following fields:

| Column | Description |
| :--- | :--- |
| `graph:id` | Unique identifier of the generated graph instance. |
| `graph:nstate` | Number of states ($N$) in the pMC. |
| `graph:ntrans` | Total number of transitions in the pMC. |
| `graph:nvar` | Number of variables ($K$) in the pMC. |
| `method:id` | Unique identifier for the method configuration. |
| `method:optimizer` | Optimization algorithm used (e.g., `AdamW`). |
| `method:nsample` | Computational budget: Monte Carlo sample count, Jacobi iteration limit, or empty for exact/Krylov solvers. |
| `method:gradient` | Gradient estimation algorithm (`SparseLU`, `BiCGSTAB`, `LogDerivative`, `UniformPath`, `JacobiIteration`). |
| `opt:status` | Execution termination status (e.g., `Success`, `Timeout`, `Fail`). |
| `opt:times` | Cumulative time across optimization steps (for `nstep == 1`, represents initial gradient computation time). |
| `opt:monotonic` | Boolean indicating whether every parameter updated monotonically (consistently in the same direction) across all steps. |
| `opt:rewards` | Reward values recorded across optimization steps. |
| `opt:first_gradient` | Gradient vector/value computed at the initial step. |

## 📈 Analyzing Results (`read_csv.py`)

A parsing and aggregation script (`read_csv.py`) is provided to process raw CSV benchmark outputs (`output.csv`, `example.csv`, or files in `Experiments/`).

### Usage

Set `file_name` inside the script to your target CSV file, then run:

```bash
python3 read_csv.py
```

### Computed Metrics

The script aggregates results across graph instances and groups metrics by method ID (`method:id`), state counts (`graph:nstate`), and variable counts (`graph:nvar`):

| Metric | Description |
| :--- | :--- |
| `time` | Average runtime (in seconds) per method. |
| `norm_time` | Runtime normalized relative to `SparseLU` on the exact same graph instance. |
| `cosine` | Cosine similarity between the method's initial gradient and the exact `SparseLU` gradient baseline. |
| `norm_dist` | Normalized relative $L_2$ error ($\|g - g_{\text{SparseLU}}\|_2 / \|g_{\text{SparseLU}}\|_2$) against `SparseLU`. |
| `norm_reward` | Average normalized reward gain vs. execution time across multi-step optimization trajectories. |
